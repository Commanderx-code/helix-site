    1. November 2, 2026Helix Toolbox

      Helix Toolbox v1.25.18

      Helix Toolbox v1.25.18, built from commit 9a47910c5ecb8fd29fc84a4e967f2da8653d9735.

      Linux x86_64 and aarch64 (ARM64), built on Ubuntu 22.04 (glibc 2.35 or newer).

      Install the package for your distribution, or run the program directly:

      # x86_64
sudo pacman -U helix-toolbox-1.25.18-1-x86_64.pkg.tar.zst   # Arch and derivatives
sudo apt install ./helix-toolbox_1.25.18-1_amd64.deb        # Debian, Ubuntu
sudo dnf install ./helix-toolbox-1.25.18-1.x86_64.rpm       # Fedora
sudo zypper install --allow-unsigned-rpm ./helix-toolbox-1.25.18-1.x86_64.rpm   # openSUSE

# aarch64 (ARM64)
sudo pacman -U helix-toolbox-1.25.18-1-aarch64.pkg.tar.zst  # Arch Linux ARM
sudo apt install ./helix-toolbox_1.25.18-1_arm64.deb        # Debian, Ubuntu, Raspberry Pi OS
sudo dnf install ./helix-toolbox-1.25.18-1.aarch64.rpm      # Fedora, Fedora Asahi Remix
sudo zypper install --allow-unsigned-rpm ./helix-toolbox-1.25.18-1.aarch64.rpm   # openSUSE

      The window (docs/GUI.md), which needs the helix-toolbox package above:

      sudo pacman -U helix-toolbox-gui-1.25.18-1-x86_64.pkg.tar.zst   # Arch and derivatives (aarch64 for ARM64)
sudo apt install ./helix-toolbox-gui_1.25.18_amd64.deb      # Debian, Ubuntu (arm64 for ARM64)
sudo dnf install ./helix-toolbox-gui-1.25.18-1.x86_64.rpm   # Fedora, openSUSE (aarch64 for ARM64)
chmod +x helix-toolbox-gui_1.25.18_amd64.AppImage && ./helix-toolbox-gui_1.25.18_amd64.AppImage   # any distribution

      Arch and its derivatives can take both packages from the repository at https://commanderx-code.github.io/Helix-toolbox instead, which pacman then updates with the rest of the system (docs/INSTALL.md).

      Check a download with sha256sum --check --ignore-missing SHA256SUMS, and where it was built with gh attestation verify <file> --repo Commanderx-code/Helix-toolbox. See docs/INSTALL.md.

      The files named helixforge-* are the same files under the name before 1.7, for copies of HelixForge to update from.

      The *-sbom.cdx.json files are CycloneDX software bills of materials: every crate in the program and the window, and the window's frontend packages.

      v1.25.18 on GitHub

    5. November 2, 2026Helix Boot

      Helix Boot v0.7.6

      Added

      • A stick a virtual machine also holds isn't written. Two systems writing one stick corrupts it. On Linux, install.sh, refresh.sh, check.sh, theme.sh and the window stop when a running libvirt VM has the stick attached as a disk, and warn when a VM is set to take it at its next start.
      • scripts/vm-stick.sh give <vm> / take <vm> hands the stick to a running VM and takes it back: unmounted here before it is attached there, and mounted here again only after it is detached. Nothing is added to the VM's settings.

      Fixed

      • The app's window opens in the middle of the screen. Where Windows put it on a small screen, the bottom row of buttons could be under the taskbar.

      Changed

      • What has been tried on real hardware, and what hasn't.
      • scripts/release.sh waits for CI on the commit it is about to release, and stops if a run failed or was cancelled.
      • CI downloads and verifies every tool (about 4 GB) on the weekly run, for a release, and when helix, tools.toml or the workflow changed. Any other push skips that, and still asks every upstream for its latest.
      • ProduKey is off by default. Windows Defender stops it being written, so a new stick no longer meets that. Tick it in the app's Tools window (or enable it in local.toml) to have it. Without that, the next update from the PC that put it on a stick takes it off again, as for any tool that is no longer chosen; a stick filled by another PC keeps it.

      Checking a download: sha256sum -c SHA256SUMS, or gh attestation verify HelixBoot.exe --repo Commanderx-code/helix-boot.

    6. November 2, 2026Helix Boot

      Helix Boot v0.7.5

      Added

      • A check watches the programs you put on the stick yourself. Portable apps and the like have no checksum from a download to be held to, so a check now remembers what each program file was and says when one has changed since the last check. If you updated it, that is why; if you didn't, something changed it, which is how a virus that infects programs shows. Helix Boot's own files are told apart and checked against their checksums as before.
      • Eject, beside Refresh in the window: what was written is flushed and the stick is ejected, so it is safe to unplug (Windows and Linux).
      • Tools… in the window: a list of every tool to tick, by category. What you choose is kept in tool-choices.json beside local.toml, which is left alone, and applies from the next Install or Update.
      • Said before the install: what antivirus will block. A tool known to be stopped by antivirus is marked flagged in tools.toml (ProduKey, so far). The Windows app names such tools before anything is copied and offers to leave them out. Unticked, they are tried as before and skipped if blocked.
      • The Linux window in the applications menu: HelixBoot-linux-x86_64 --add-launcher adds it, with its icon, for you only; --remove-launcher takes it out.
      • After an update of the app: "Start the new version now?"
      • self-update for the Mac program and HelixBoot.sh (also in its menu): the latest release's file, checked against the sha256 GitHub gives for it, in this one's place.
      • helix pack --public: a pack with only what anyone can download, as the project ships it, so it can be shared. It is planned by a configuration that has never seen your folder: nothing from local.toml (your tools, your settings, what you switched off), tool-choices.json or byo/ (your files, icons and splash) can be in it, and Lazarus PE, your own build, is left out. The download cache is still yours, so a tool you pointed somewhere of your own is left out as well, and so is any cached copy that didn't come from the project's source for that tool: boot images, apps, Ventoy, the menu's platform and the bundled programs alike. What is taken is held to the cache's record as well: it has to be in that tool's own folder of the cache and still have the checksum it had when it was downloaded, a folder included. Whatever can't be checked is left out and named. (A cache from before this version has no checksum for the PortableApps.com platform's folder: helix fetch --force portableapps records one.)
      • Making any pack re-checks Ventoy and the bundled HelixBoot.exe against the checksums they were verified to have when downloaded, as it does the apps.
      • helix pack --split: also cuts the pack into pieces (2 GiB if not said) in a folder beside it, with its checksum, a README, and scripts for Windows and for Linux and Mac that join the pieces, check the result and start the installer: for uploading or sending.

      Checking a download: sha256sum -c SHA256SUMS, or gh attestation verify HelixBoot.exe --repo Commanderx-code/helix-boot.

    8. October 25, 2026Touchdown

      Touchdown v0.1.0

      Touchdown v0.1.0

      First public release of Touchdown, a keyboard-driven NFL scores and stats dashboard for the terminal.

      Highlights

      • Live scores, weekly matchups, conference standings, and a favorite-team dashboard.
      • Team schedules, next kickoff, bye weeks, season leaders, and game details.
      • Configurable favorite team and color theme, cached responses, and optional desktop alerts.
      • td shortcut when installed from source with make install.

      Downloads

      Choose the archive for your operating system and CPU: Linux, macOS, or Windows on AMD64 or ARM64. Each archive contains the executable, README, and MIT license. Download SHA256SUMS to verify the archive's checksum.

      The release binaries are unsigned. Builds for all six targets completed successfully; runtime smoke testing was performed on Linux AMD64. macOS, Windows, and ARM64 runtime behavior has not been tested on those systems.

      Touchdown uses publicly accessible, undocumented ESPN endpoints. Live data and stats depend on those endpoints remaining available.

      v0.1.0 on GitHub
